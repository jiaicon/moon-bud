# 游客态进入应用 · 设计（2026-10-20）

取代 2026-10-16 设计里"游客只能看欢迎页 + 只读预览"的那一条边界。

> **2026-10-21 修订（HANDOFF §（十八）），本文件以下几处已作废，照本施工前先读这一段**：
> 数据位不再给短横线 `—` 而写「无」；**所有"需要登录吗"弹窗取消**（游客点了就是无反应）；
> 要读全家数据的入口对游客**不画**（首页记一笔九宫格与统计入口、记录页导出、提醒页提醒中心）；
> 只改本地状态的控件（类型芯片、☰、日期区间、提醒三段）**放开给游客点**。
> "我的"那七行的弹窗也一并撤掉——它当初就被记为"本项目里最重的一种引导"，用户现在要的是静默。

## 意图与原因

现在没登录的人被关在应用外面：启动落在一页欢迎页上，看什么都要看假数据演示页。
用户希望没登录也能走进应用本身，四格 Tab 都能翻，翻到的就是真页面；
"要不要登录"这件事由页面自己在他想看的那一幕里说清楚，而不是由门口那块牌子说。

一句话：**应用本身变成游客的预览。**

## 已由用户定下的形状

1. 未登录可以进入并浏览真实页面（首页 / 记录 / 提醒 / 我的 四格都在）。
2. `pages/welcome/index` **彻底删除**，首屏是首页。
3. 现有功能预览页原样搬进"我的"，作为教学页；内容不改写。
4. 未登录的引导**只做在空状态里**：不加顶部横幅，不加切 Tab 时的弹提。
5. 游客**不展示任何"新增"按钮**（记一笔、添加孩子、设一个提醒、两颗 FAB）。
6. "我的"里所有行**都保留**，点了弹"登录确认"，确认去登录页。
7. 免登录白名单三行：教学、主题设置、关于。
8. 游客被送到登录页以后，登录成功**统一回首页**。
9. 会话过期被踢回来：不拍到登录页脸上，落到首页游客态 + 一句提示。

## 非目标

- 不做游客本地草稿（"先记着，注册后归他名下"）——已问过，用户选了"不展示新增按钮"。
- 不给真页面注入演示数据。游客看到的就是空，空话说的是空。
- 不动后端：`/api` 除已有的 `auth: false` 端点外仍全部要 JWT。
- 不新增推送、角标、同步行为。

## 反目标

- **不许把"我不知道"和"还没登录"演成"没有"**。这是本项目反复修过的错
  （`children-unknown-vs-none`、C-2、隐患 5）。游客态必须是判定出来的第三种状态，
  不能是"数据请求失败后掉进空数组"的那种空。
- 不要做成"点哪儿都弹窗"的应用。弹窗只在"我的"那七行；其余地方靠空状态说话。

## 约束（现状，已核对源码）

- `pages.json:5` 第一条是 `pages/welcome/index`，即启动页；`pages.json:2` 有注释说明这一点。
- `stores/auth.ts:34` `isLoggedIn = s.token !== null`，**纯内存**；冷启动必须先 `bootstrap()`
  （`:134-141`，无 refreshToken 时 `:145-147` 直接 `status='idle'` 返回，不发请求）。
- `api/http.ts:98` `hadSession = needsAuth && getAccessToken() !== null`；游客 401 **不**触发
  会话过期上报（`:133-134`、`:144`），只抛 `ApiRequestError`。
- `stores/auth.ts:209-212` `handleSessionExpired()` 现在 `clearSession()` + `reLaunch('/pages/welcome/index?expired=1')`。
- `notifications/unread.ts:14` 无 access token 时返回 `null`，`tab-badge.ts:18` 收到 `null` 什么都不动。
- 四个 Tab 页都以 `familyStore.load()` + `familyId`/`childId` 为闸门，页面骨架假定有家庭。
  首页的分支由 `pages/home/home-view.ts:22-27` 的 `decideHomeView` 决定，已有 `create-family` 分支。
- `pages/preview/index.vue` 的数据全在本地 `src/preview/mock-data.ts`，靠 `@moonbud/shared` 的类型；
  唯一入口是 `welcome/index.vue:61`。
- `pages/login/index.vue` 已支持 login/register/join 三挡（`:16-20`，可用 `?mode=` 预选）。
- 删除 welcome 会牵动的测试：`pages/__tests__/welcome-session.test.ts`（读该 .vue，删页即 ENOENT）、
  `stores/__tests__/auth.test.ts:192,232`（断言 reLaunch 的 URL）；
  `pages/__tests__/pull-refresh.test.ts:27` 会遍历 `pages.json` 每条 path 并要求同名 .vue 存在。

## 设计

### 1. 第三种状态：`unknown / guest / member`

游客态不能写成 `!isLoggedIn`，因为冷启动那一瞬 `isLoggedIn` 是 false 而真相是"还没问出来"。

- 在 `stores/auth.ts` 暴露一个判定完成的信号（建造者可自选实现：新增 getter `sessionResolved`
  或复用 `status`），语义是三态：**会话未知 / 游客 / 已登录**。
- 只有判定为"游客"才渲染游客空状态；"会话未知"沿用各页已有的 loading 骨架。
- App 冷启动（`App.vue:28-33`）已经在 `onLaunch` 里 `bootstrap()`，Tab 页要等它而不是各自问一遍。

### 2. 首屏与启动

- `pages.json` 第一条改为 `pages/home/index`（tabBar 首页），`pages/welcome/index` 条目与目录删除。
- `utils/preview-visited.ts` 连同三处调用一起删（`preview/index.vue:11` 写、`welcome:26` 读、
  `auth.ts:178` 清）。它存在的唯一理由是欢迎页那颗"继续注册"的标签。
- 会话过期：`handleSessionExpired()` 改成 `clearSession()` → `switchTab('/pages/home/index')`
  + 一次性提示（`uni.showToast`，文案见 §4）。**不再 reLaunch 到欢迎页。**
- 退出登录：`pages/profile/index.vue:77` 的 `reLaunch('/pages/welcome/index')` 改成
  `reLaunch('/pages/home/index')`，退出确认文案不动。

### 3. 游客能看什么、不能伸手做什么

> **2026-10-20 当天由用户改定（见 HANDOFF（十六））**：下面这张表的"隐藏"只对**写入控件**成立。
> 用户看了实现后要求"未登录的游客，可以将原本页面的功能都显示出来，引导登录的组件放在空白区域"，
> 于是规矩变成：**骨架照画，值给短横线，引导坐内容空白区，每一处可交互都只问一句**。
> 首页那两个切换器不再是整块隐藏，而是画两格 `—` 的占位（"显示短横线吧"）。

四格骨架都在，但**凡是会产生写入的控件在游客态不渲染**（不是置灰、不是弹回，是不出现）：

| 页面 | 游客态隐藏 | 游客态保留 |
|---|---|---|
| 首页 | 记一笔的落点、统计入口（都改成点了问一句）；FAB 本来就没有 | 两格切换器占位（`—`）+ 概览三行（`—`）+ 记一笔九宫格 + 统计入口 + 引导 |
| 记录 | FAB、待同步那条（出箱队列读的是本机存储，可能留着上一个账号的行）；孩子/记录人两行是数据驱动，游客没有就不画 | 筛选行（类型芯片、☰、日期区间、导出）+ 引导，点了只问一句 |
| 提醒 | FAB、"＋ 设一个提醒" | 三段分段 + 提醒中心链接 + 引导，点了只问一句 |
| 我的 | 无 | 全部行（§5） |

游客的判定要在**任何取数之前**短路：四个 Tab 页的 `onLoad` 先等 `bootstrap()` 落定，
是游客就不发 `familyStore.load()`、不发 `childStore.load()`、不 `outboxStore.load()`。
`currentFamilyId` 与待同步队列都存在设备本地、且不随 `clearSession()` 清掉
（退出会清，会话过期按设计不清——那些记录属于这一个账号，重新登录后还要用），
所以游客态一旦继续往下取数，就会把上一个账号的"待同步"演成这个游客的。

游客空状态**自带一条去登录的路**：主按钮"登录 / 注册"，次一级文字"先看看它能做什么"跳教学页。
这是引导唯一出现的地方（§4）。

### 4. 空状态文案

短句，说清"这里为什么是空的"和"登录之后会多出什么"，不许出现"没有记录"这种把游客演成空的措辞。

- 首页：`登录后，这里会显示宝宝今天吃了多少、换了几次尿布。`
- 记录：`记录都存在你家的账号里。登录后能看到全家人记的每一条。`
- 提醒：`喂药、体检、该睡觉——登录后到点全家一起收到。`
- 按钮：`登录 / 注册` → `/pages/login/index`；辅助文字：`先看看它能做什么` → `/pages/preview/index`
- 被踢回来时的那句提示：`登录已过期，重新登录就能接着记。`

### 5. "我的"页在游客态

- 顶部身份行：`未登录`（现状 `:100` 已经是这个），下面一颗主按钮 `登录 / 注册`。
  这颗按钮是唯一免弹窗的登录入口。
- 分组与行**照常全部列出**（外观 / 提醒 / 家庭 / 账号 / 关于）。这一页其实有**八个**能点的行，
  不是七个；数值位在游客态留空而不是写"还没有家庭"（家庭名）；
  `重复提醒提示` 那一位写"默认"是真的（本机确实一处都没改），保留。
- 点击行为分两类：
  - **免登录三行**：教学（`/pages/preview/index`）、主题设置、重复提醒提示。
    后两行改的都是本机偏好，不需要账号；把"改个配色"也弹一次登录是荒唐的。
    `关于` 那一段只是文字卡，本来没有可点的行。
  - **其余六行弹确认**：家庭设置、成员管理、邀请家人、切换家庭、修改密码、提醒中心，
    外加`时区`——它不是 `go()` 行而是一个 `<picker>`，游客态改成一个同样式的行，
    点了弹确认，不让选择器打开（在游客身上打开选择器再告诉他不能保存，是把人耍了一遍）。
    弹窗：标题 `需要登录`，正文说明这一行登录后能做什么，确认 `去登录`，取消 `再想想`；
    确认 → `navigateTo('/pages/login/index?mode=register')`，取消 → 什么都不做。
    走 `utils/confirm.ts`（`showModal` 不可用时宁可什么都不做）。
- `退出登录` 那颗按钮游客态不出现（没有会话可退）；`<theme-switcher>` 卡片保留（本机生效）。
- `切换家庭` 一行维持现状：本机只有一个家庭时不出现（`canSwitchFamily`）。游客没有家庭，
  这一行在游客态也不出现——它属于"假入口不摆出来"那条既有规则，不算违反"全部都在"。

### 6. 教学页

- 路由、内容、mock 数据都不动，只是入口从欢迎页搬到"我的"的白名单行，标题改成 `功能教学`
  （`pages.json` 的 `navigationBarTitleText`）。
- 页内原有的两颗 CTA 保留：右上角"注册/登录"pill、底部"开始使用"。它们是引导，不是新增按钮。
- 从游客空状态的"先看看它能做什么"进来时，返回能回到原页面（`navigateTo` 自然支持）。

### 7. 注册与邀请码的入口

欢迎页一死，原先它承担的三个入口要有新位置：

- 注册/登录/加入：登录页三挡已经存在，"我的"的主按钮和白名单弹窗都送进登录页。
  默认落在 `mode=register` 还是 `mode=login`：见"我的判断"§8 第 4 条。
- 扫码加入：`pages/join/index.vue:50-54` 已经有"未登录 → 去登录"的分支，要保证带着 `code`
  落到登录页并预选 join 挡（`login/index.vue` 的 `onLoad` 已支持 `?code=` + `mode=join`）。

### 8. 我的判断（未经用户确认，可推翻）

1. `preview-visited.ts` 整个删掉。留着它只会有人写、没人读。
2. 游客态**不请求** `/api/notifications`、不启动 `due-watch`、不进出箱队列——现状已经如此，
   只补测试锁住。
3. Tab 页要等 `bootstrap()` 落定再判定游客，判定时机用 store 的信号而不是各页自己 `await`，
   免得四份实现漂移。
4. "我的"那颗主按钮送进 `?mode=register`：站在这一页又还没登录的人，最可能是新用户想试试；
   已有账号的人自己会切挡。登录页三挡是并列的，代价只是多点一下。
5. 游客空状态里"先看看它能做什么"这一条辅助文字，三页都放。它把唯一一份产品介绍送到了
   三个真正会撞上空状态的地方。
6. `pages.json:2` 那条注释、文档里所有"欢迎页"的说法一并改掉，不留假描述。
   `docs/superpowers/{specs/2026-10-16-moonbud-design.md,plans/2026-10-16-mobile-app.md,HANDOFF.md}`
   与 `apps/mobile/BUILD.md` 里的引用只加一条指向本设计的说明，历史正文不重写。
7. Android 启动图（splash）是构建配置里的另一回事，与欢迎页无关，本次不动；
   `apps/mobile/BUILD.md:208` 提到欢迎页的那句要改。

## 交给建造者的自由度

- 三态判定用什么类型（getter / `status` 加一个值 / `computed`）由建造者选，只要四个 Tab 页共用一份。
- 游客空状态用现成的 `<empty-state>` 组件还是新起一个带按钮的变体，都行；
  要求是同一份文案在三页里由一处定义，别复制三份。
- 白名单/弹窗那套判断，做成一个可测的小函数（输入行目标，输出"直接进 / 需要登录"），
  别散在模板的 `@click` 里。

## 验证

- 门控测试：`pages.json` 首条是首页；仓库里再无 `pages/welcome` 引用；四个 Tab 页各有游客分支且
  游客分支不出现写入控件；"我的"的白名单三行没有包在登录确认里，其余七行有；
  教学页仍只有 mock 数据源。
- 单测跑 `npx vitest run`（`apps/mobile`，现 563 个），改完不得少于现有数且全绿；
  `npx vue-tsc --noEmit`；`pnpm --filter @moonbud/mobile build:h5` 与 `build:app`。
- 真机之外，H5 里用浏览器实测：清掉 token 冷启动 → 首页游客空状态；切三格都有引导；
  "我的"点家庭设置弹确认、取消不留痕、确认到登录页；注册一个新账号后回首页看到真数据；
  手动把 refreshToken 弄失效触发过期 → 落首页 + 一句提示，不是白屏也不是"没有记录"。
  用完的 QA 账号按既有顺序删干净。

## 风险与代价

- 欢迎页是这个应用对新用户讲故事的那一页。删掉之后，产品介绍只剩教学页一处，而它现在在"我的"里，
  一个人得先走进"我的"才看得见。用户明确选了"彻底去掉"，此条风险归他。
- 七个行都用弹窗挡，是本项目里最重的一种引导；如果之后觉得吵，改的只是"我的"一处。
- `unknown/guest` 判定如果做错，冷启动会闪一下"未登录"再变真数据。测试要专门盯这一眼。
